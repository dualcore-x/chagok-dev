## 1. 앱 한 줄 소개

차곡 · 공용차를 바꿔 타도 차에 남은 문제와 업무가 끊기지 않도록, 누가 받았고 무엇이 남았고 무엇이 끝났는지까지 차 화면에서 이어 주는 인계 앱.

## 2. 기획 배경 · 창의성(Pain Points & Needs)

회사 공용차는 여러 사람이 바꿔 탑니다. 그런데 앞사람이 알던 차 상태와 끝내지 못한 일은 단톡방·메모지·구두로 흩어져, 차를 넘겨받는 사람에게 제때 닿지 않습니다.

- **전달이 끊깁니다.** 소리·충전 상태 같은 차 문제와 트렁크 물건·충전 케이블 위치 같은 업무 정보가 메신저나 메모지에 남아 다른 대화에 묻힙니다. [팀 결정: 두 사람이 겪은 사례 1~2줄]
- **받았는지, 끝났는지 모릅니다.** 메신저의 "읽음"은 그 사람이 차 문제를 이해했다는 뜻도, 처리했다는 뜻도 아닙니다. 다음 사람이 이미 끝난 일을 또 하거나 남은 일을 놓칩니다.
- **필요한 순간에 없습니다.** 정보가 필요한 때는 차에 타서 출발하기 전, 그리고 목적지에 도착해 주차했을 때입니다. 그 순간 폰의 단톡방은 열려 있지 않습니다.

**주목한 고객:** 업무용 차를 여러 명이 비슷한 비중으로 나눠 타고, 앞사람과 얼굴을 보지 못한 채 키만 주고받는 경우가 있는 조직. 그중 1순위는 **지점 영업용 차**입니다. 영업사원 여러 명이 업무용 차 한 대를 돌려 타며 납품 물건·거래처 정보·충전 상태를 넘겨야 하고, 시연 장면(샘플 박스 전달, 충전 케이블 위치)도 이 상황입니다.

**왜 지금 해결해야 하는가:** 차 문제를 놓치면 정비가 늦어지고, 업무 물건을 놓치면 같은 곳을 다시 다녀와야 합니다. 국내 법인차 관리 서비스(예: 카택스)는 스마트폰 앱 운행일지, 유류비 정산, 차량 예약, 정비 주기 알림을 제공하고 차량 메모 입력란도 있습니다([카택스 기능](https://cartax.biz/features), [메모·정비 안내](https://info.cartax.biz/f7e96fb1-1d6b-47b8-91c3-39686e748501), 2026-11-07 확인). 다만 공개된 안내에서는 메모를 다음 운전자가 받았는지, 그 일이 끝났는지를 운전자별로 남기는 기능은 확인되지 않았습니다. 이 앱은 관리 기록이 아니라 운전자가 바뀌는 순간, 차 화면에서 그 빈틈을 메우는 데 집중합니다.

## 3. 앱 주요 기능 및 차량 특화 요소 · 차량특화성, 창의성

### 주요 기능

| 기능 | 해결하는 문제 | 확인 수준 |
| --- | --- | --- |
| 운전자별 인수 요약 | 이 운전자에게 새롭거나 바뀐 인계, 계속 남은 중요한 일만 먼저 보여 줌. 이미 확인한 일반 정보는 반복하지 않음 | Pleos 에뮬레이터 확인 |
| 확인과 처리의 분리 | "확인했어요"는 봤다는 기록, "처리 완료"는 메모와 함께 끝냈다는 기록. 한 사람의 확인이 다른 사람에게 넘어가지 않고, 내용을 고치면 이미 본 사람에게도 "내용 바뀜"으로 다시 보여 줌 | Pleos 에뮬레이터 확인 |

| 목적지 업무 우선 | 내비 목적지가 등록 장소면 그곳에서 할 일을 요약 맨 앞에 | Pleos 에뮬레이터 확인 |

| 차량 상태 자동 기록 | 인계를 남길 때 주행거리·배터리를 차에서 받아 붙임. 못 받으면 "미수신"으로 표시하고 0으로 채우지 않음 | Pleos 에뮬레이터 확인 |
| 말로 남기기 | 차량 음성 인식으로 받아 적고, 주차 중에 확인·수정한 뒤 저장 | Pleos 에뮬레이터 확인 |

### 차량에서만 가능한 경험

1. **인계가 일어나는 곳에서 받습니다.** 차에 타서 운전자를 고르는 순간이 곧 인수 시점입니다. 폰 앱은 열어야 보이지만 차 화면은 탈 때 이미 앞에 있습니다.
2. **주행·정차 상태를 따릅니다.** 기어가 P일 때만 입력을 열고, 주행 중에는 Pleos 플랫폼 정책대로 화면을 쓰지 않습니다. 상태를 모르면 입력을 막습니다.
3. **목적지와 도착을 압니다.** 내비 목적지로 그곳의 할 일을 먼저 보여 주고, 도착해 주차하면 다시 알립니다.
4. **차가 아는 값은 사람이 적지 않습니다.** 주행거리와 배터리를 인계와 함께 자동으로 남깁니다.
5. **손을 덜 씁니다.** 말로 남기고, 저장 전 화면에서 확인합니다.

## 4. 주요 사용 시나리오

**등장인물:** 공용 1호차를 함께 쓰는 김하늘·이도윤·박서연(가상 인물). 등록 장소는 거래처 한빛상사와 본사 주차장.

1. **김하늘이 반납하며 남깁니다.** 주차한 차 화면에서 "운전석 와이퍼에서 끽 소리가 나요. 정비 예약이 필요해요."를 중요한 일로 남깁니다. 트렁크의 샘플 박스(한빛상사 전달용)와 충전 케이블 위치(본사 주차장)도 남기고 반납합니다. 남길 때의 주행거리와 배터리가 함께 기록됩니다.
2. **이도윤은 필요한 것만 받습니다.** 차에 타서 이름을 고르면 "이번 목적지 한빛상사에서 할 일이 1건 있어요. 지난 사용 이후 새로 생기거나 바뀐 인계가 3건 있어요. 그중 1건은 중요해요."가 뜹니다. 내비 목적지가 한빛상사라 샘플 박스가 맨 위에 옵니다. 와이퍼와 케이블에 "확인했어요"를 누릅니다. 확인은 봤다는 기록일 뿐, 끝냈다는 뜻이 아닙니다.
3. **목적지에서 끝내고 반납합니다.** 주행 중에는 화면을 쓰지 않습니다. 한빛상사에 도착해 주차하고 "도착했어요"를 누르면 그곳 인계가 다시 뜹니다. 샘플 박스를 "구매팀 김OO님께 전달" 메모와 함께 처리 완료로 남기고, 바뀐 케이블 위치를 고친 뒤 반납합니다.
4. **박서연에게는 남은 일만 갑니다.** 앱을 다시 켜도 기록은 그대로입니다. 박서연에게는 끝나지 않은 와이퍼 문제와 바뀐 케이블 위치만 새 인계로 가고, 샘플 박스는 누가 언제 어떻게 끝냈는지 이력으로만 보입니다. 이도윤의 확인은 박서연의 확인으로 치지 않습니다.

이 흐름은 시연 영상의 대본(`docs/demo-script.md`)과 같고, 화면 문구는 자동 테스트(`DemoScriptTest`)로 검사합니다.

## 5. 개발 계획 · 기술 활용성

### 구현 방식

- Kotlin 2.1·Jetpack Compose 네이티브 Android 앱, Pleos Connect(AAOS) 대상, minSdk 28 · targetSdk 35, release는 v3 서명(Pleos 서명키 교체 요건).
- 인계 규칙(운전자별 확인, 처리, 요약, 목적지·도착 판단, 음성 중단 규칙)은 Android에 의존하지 않는 core 모듈에 두고 단위 테스트 36개로 검사합니다. 시연 대본의 화면 문구도 테스트(`DemoScriptTest`)로 고정합니다.
- Pleos SDK는 차량·내비 어댑터와 음성 어댑터 두 곳에서만 부릅니다. 화면과 규칙은 어댑터가 넘겨준 값과 이벤트만 봅니다. Pleos 서비스가 없는 기기에서는 같은 자리에 시뮬레이션이 들어가고 화면에 "시뮬레이션"으로 표시합니다.
- 기록은 기기 안에 저장합니다(1차). 앱을 강제 종료하고 다시 켜도 진행 중인 인계와 확인·처리 기록이 남는 것을 확인했습니다.
- PR마다 GitHub Actions가 core 테스트, lint, debug·release 빌드를 돌립니다.

### 차량 환경에 맞춘 처리

에뮬레이터에서 SDK를 직접 시험해 확인한 동작에 맞춰 만들었습니다(`docs/sdk-checks.md`).

- **값이 없으면 없다고 표시합니다.** 차량 값은 출처(차량·직접 입력·시뮬레이션)와 수신 상태를 함께 저장합니다. 못 받은 값은 0으로 채우지 않습니다. 주행거리·배터리는 화면에 "미수신"으로 표시하고, 이 에뮬레이터처럼 연료 잔량을 지원하지 않는 EV에서는 연료를 미수신으로 저장하되 화면에는 보여 주지 않습니다. 화면 상단에는 실행 환경(에뮬레이터/실차)을 표시합니다.
- **주행 상태를 따릅니다.** 기어 P일 때만 입력을 엽니다. 말로 남기는 중에 D로 바꾸면 듣기를 멈추고 마이크와 오디오 우선권을 돌려줍니다. 주행 중에는 Pleos 플랫폼이 앱 화면을 가리므로 주행 중 화면은 따로 설계하지 않았습니다.
- **다른 소리에 양보합니다.** 음성은 `GAIN_TRANSIENT_MAY_DUCK` · `USAGE_ASSISTANT`로 오디오 우선권을 요청하고, 다른 앱이 우선권을 가져가면 즉시 멈춥니다(다른 앱의 요청으로 시험했고, 실제 통화·내비 안내 음성과 겹치는 경우는 미확인). 끝나면 반드시 반납해 다른 소리가 계속 작아진 채로 남지 않게 합니다. 회귀 확인 중 잠깐 잃은 우선권을 반납하지 않던 버그를 찾아 고쳤고, 차량 오디오 서비스의 우선권 목록으로 확인했습니다.
- **차량 서비스가 다시 떠도 이어집니다.** 차량·내비 서비스를 강제로 종료해도 SDK가 다시 연결되고, 주행거리·배터리 갱신과 목적지 표시가 이어지는 것을 확인했습니다. 차량 서비스 연결은 완료 신호가 없어 첫 조회가 성공할 때까지 다시 시도합니다.
- **내비에서 직접 잡은 경로도 반영합니다.** 내비 화면에서 직접 시작한 경로는 SDK 알림이 오지 않아 10초마다 목적지를 다시 조회합니다.
- **도착 근거를 구분합니다.** 내비 도착 신호와 운전자의 "도착했어요"를 따로 기록하고, 직접 확인한 도착은 화면에 "도착 · 직접 확인"으로 표시합니다.
- **일반 앱 권한으로 읽을 수 없는 경고등은 범위에서 뺐습니다.** 경고등 API는 시스템 권한(`PRIVATE_CAR_SAFETY`)이 필요합니다.

### 검증

- Pleos Connect Emulator v2.1.0(API 34, arm64)에서 Virtual Console로 기어·주행거리·배터리를 바꾸며 확인했습니다. 확인 절차는 스크립트(`tools/vc.sh`)와 시험용 앱(`tools/probe`)으로 남겨 다시 돌릴 수 있습니다.
- 회귀 시나리오 10개(목적지 변경, 도착 후 재주차, 서비스 재시작, 백그라운드 복귀, 오디오 우선권, 강제 종료 후 재실행, 주행 중 듣기 중단)를 기능 동결일(11/8)에 다시 돌려 모두 통과했습니다(`docs/regression.md`).
- 서명된 release APK를 새로 설치해, 남기기 → 반납 → 다음 운전자 요약 → 처리 완료 → 재실행까지 확인했습니다.

### 개발 범위와 제약 (1차 제출 시점)

- 차량 1대 · 운전자 3명 · 등록 장소 2곳, 프로필 선택으로 사용 시작(PIN 없음).
- Pleos Connect Emulator v2.1.0에서 검증했습니다. 실차는 확인하지 않았습니다.
- 에뮬레이터에서는 내비 도착 신호가 오지 않아 도착은 화면의 "도착했어요"로 직접 확인합니다(화면에 "도착 · 직접 확인" 표시).
- 등록 장소 두 곳은 시연용이라 에뮬레이터 내비에서 검색되지 않습니다. 시연에서는 목적지 칩이나 확인용 앱으로 목적지를 정합니다.
- 한글 입력은 Pleos 에뮬레이터의 기본 차량 키보드로 확인했습니다(11/9).
- 도착 표시는 앱을 강제 종료하면 초기화됩니다. 인계와 확인·처리 기록은 유지됩니다.

### 2차 PT까지 고도화 계획

## 6. 기대효과 및 발전 가능성 · 사업성

| 항목 | 내용 |
| --- | --- |
| 사용자 가치 | 차 문제의 누락·중복 처리 감소, 인계 확인 이력, 남길 때 차가 아는 값은 자동 기록 |
| 타깃 고객 분석 | 업무용 차를 여러 명이 나눠 타는 조직. 구매자는 차량 관리 담당자, 사용자는 운전자. 규모 참고: 2025년 서울 등록 차량 3,158,598대 중 법인·사업자 명의가 435,060대([서울시 교통 통계](https://news.seoul.go.kr/traffic/archives/516115) 표 4). 이 중 여러 명이 나눠 타는 차의 비율은 공개 통계가 없어 쓰지 않습니다. 1순위 고객은 **지점 영업용 차**(영업사원 여러 명이 한 대를 돌려 타는 경우). |
| 예상 MAU | 산정식: **MAU = 도입 차량 수 × 차량당 한 달 운전자 수**. 시나리오의 차량당 운전자는 3명. 도입 차량 수는 Pleos Connect를 탑재한 업무용 차량 안에서만 늘 수 있어 탑재 대수가 상한입니다. 현대차그룹은 2026년 5월 더 뉴 그랜저부터 탑재를 시작해 2030년까지 2,000만 대 탑재 차량 확보를 목표로 밝혔습니다([현대자동차그룹, 2026-04-30](https://www.hyundaimotorgroup.com/ko/story/pleos-connect-next-generation-infotainment-system)). 현재 누적 탑재 대수와 그중 업무용 차 비율은 공개 자료가 없어 쓰지 않습니다. 1년 차 목표: 도입 **300대** × 3명 = **900 MAU**. Pleos Connect 탑재 업무용 차가 아직 많지 않은 첫해라 보수적으로 잡았습니다. 시장 전체 숫자를 MAU로 쓰지 않음 |
| Retention Rate | 제안 지표: **월간 활성 차량 유지율** = 지난달 인수·반납 기록이 있던 차량 중 이번 달에도 기록이 있는 차량 비율. 보조 지표: 새 인계를 받은 운전자 중 "확인했어요"를 누른 비율. 차를 탈 때마다 쓰는 흐름(인수 요약 → 반납)이라 사용 빈도가 차량 이용 횟수를 따라감 1년 차 목표 **80%** (차량 교체·운행 중단을 감안). |
| 수익 모델 | **차량당 월 구독.** 관리자 화면(열린 일·처리 이력)을 포함하고, 도입 차량 수에 비례해 매출이 늘어 MAU 산정식과 같은 단위로 계산됩니다. 가격은 시범 운영 뒤 정합니다. 배포는 Pleos App Market 기업용 배포를 검토합니다. |
| 향후 확대 계획 | 관리자 웹(열린 일·처리 이력), 서버 동기화, 여러 차량, 정비 업체 연동, Gleo 호출(승인 시). 모두 **계획** |
