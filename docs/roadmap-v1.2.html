개발 합치는 방식

  • feat/handover-*, feat/pleos-* 등 기능 브랜치와 작은 PR 사용.
  • main은 설치 가능한 상태 유지. 모델 변경은 먼저 두 사람 합의.
  • 앱 담당은 가짜 어댑터로 화면 개발, 연동 담당은 계약 테스트로 연동 개발.
  • 하루 끝에 “완료·막힘·내일 받을 것” 세 줄과 최신 APK/PR 공유.

수요 확인은 개발과 병행

  • 기본안: 앱 담당 운전자 2명, 연동 담당 운전자 1명 + 관리자 1명. 아는 사람에 맞춰 바꿔도 된다.
  • 최근 넘겨받지 못해 불편했던 실제 사례와 기존 해결법을 묻는다.
  • 11/5까지 반복 사례가 약하면 직군을 좁히고, 없는 수요를 통계로 대신하지 않는다.
  • 민간 공용차를 첫 대상으로 유지. 공공시장 수치·감사 대체 주장은 확대하지 않는다.

04

먼저 합의할 연결 계약

아래는 설계 제안이며 구현 완료된 API가 아닙니다. SDK 객체를 화면에 직접 전달하지 않고 값과 이벤트로 바꿔 전달합니다.

저장 모델 · 앱 담당 주도

Note
  id, vehicleId, authorId, createdAt, contentUpdatedAt
  anchor: VEHICLE | PLACE | ITEM
  kind: TASK | REFERENCE
  text, targetPlaceId?, importance
  taskState: OPEN | DONE
  referenceState: ACTIVE | ARCHIVED
  snapshot: value + source + observedAt + availability

Receipt
  noteId, driverId, sessionId
  presentedAt?, acknowledgedAt?

Resolution
  noteId, actorId, action: DONE | REOPEN
  performedAt, comment

DriveSession
  id, vehicleId, driverId, startedAt, returnedAt?

TASK와 REFERENCE는 해당 상태만 사용. “화면/음성으로 전달”과 “사용자가 확인”도 분리. 운전자의 가장 최근 acknowledgedAt보다 contentUpdatedAt이 늦으면(>) 다시 보여준다. contentUpdatedAt은 본문·중요도·대상 장소 수정과 재열기 때만 갱신하고, 완료·보관·전달 기록으로는 바꾸지 않는다. 기기 시계가 되돌아가면(헤드유닛 시간 동기화 전, 에뮬레이터 스냅샷 복원) 수정된 노트가 다시 안 뜰 수 있어, 시연·테스트는 Cold boot로 하고 알려진 제약으로 기록한다. 버전 이력(revision)은 기기 간 동기화가 생기는 2차에 필요하면 추가한다.

연동 포트 · 연동 담당 주도

VehicleContextSource
  capabilities, currentSnapshot
  events: parking / speed / destination / arrival
  availability: AVAILABLE | STALE | UNAVAILABLE
  source: VEHICLE | USER | SIMULATED
  runtime: EMULATOR | VEHICLE  (앱 전체 1개)

SpeechPort
  listen() → partial / final / error / cancelled
  speak(text) → completed / interrupted / error
  stop(), release()

HandoverService · 앱 담당 구현
  startSession(driverId), createNote(...)
  getBriefing(sessionId), acknowledge(noteId)
  resolve(noteId, comment), reopen(noteId)
  returnVehicle(sessionId)

미수신을 0으로 채우지 않음. SDK를 거친 값은 에뮬레이터여도 VEHICLE, 앱이 만든 가짜 값만 SIMULATED. 실행 환경은 화면 구석에 자동 표시하고, 영상·기획서에는 “에뮬레이터에서 검증”으로 적는다. 통화·내비와의 우선순위, 권한·연결 오류는 연동 담당 어댑터가 전달하고 앱 정책이 처리한다.

확인 ≠ 해결

B가 확인해도 일은 OPEN일 수 있습니다. C에게는 별도의 확인 기록을 만들고, 완료 동작에는 처리자와 시각을 남깁니다.

주차 ≠ 목적지 도착

P 전환만으로 물건을 알리지 않습니다. 대상 장소·도착 근거·주차·세션을 함께 확인합니다. 값이 없으면 직접 확인 흐름으로 전환합니다.

발화는 다시 판단

포커스가 돌아와도 무조건 이어 읽지 않습니다. 목적지와 노트 상태, 취소·만료를 재확인해 필요한 안내만 재생합니다.
