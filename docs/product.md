# 제품 범위

기준일: 2026-11-09(동결 후 main 기준). 연동 담당의 「공용차 인계노트」 기획과 로드맵 v1.2를 기준으로 합니다. 기획서·접수양식에 기능을 적을 때는 아래 "구현 상태" 표의 구분을 그대로 씁니다.

## 한 문장

공용차를 바꿔 타도, 차량에 남은 문제와 업무가 끊기지 않도록 이어주는 인계 앱. 메모를 남기는 데서 끝나지 않고 **누가 전달받았고, 무엇이 남았고, 무엇이 끝났는지**까지 이어지는 것이 중심입니다.

## 1차 제출(11/12) 범위

차량 1대 · 운전자 3명 · 등록 장소 2곳(한빛상사, 본사 주차장)을 앱에 고정합니다. 운전자 식별은 프로필 선택뿐입니다(PIN 없음).

## 구현 상태

- **Pleos 에뮬레이터 확인:** Pleos Connect Emulator v2.1.0에서 실제 앱과 SDK로 동작을 봤습니다. 실차에서는 확인하지 않았습니다.
- **일반 에뮬레이터 확인:** 구현했고 core 단위 테스트와 구글 AAOS 에뮬레이터(시뮬레이션 차량·음성)로 확인했지만 Pleos 에뮬레이터에서는 아직 안 봤습니다.
- **미확인:** 코드는 있으나 에뮬레이터에서 재현할 수 없어 동작을 보지 못했습니다.
- **계획:** 구현하지 않았습니다. 기획서에는 "계획"으로만 씁니다.

## 데이터 출처와 실행 환경 표시 (Q05)

영상과 기획서에서 실제 값, 직접 입력, 시뮬레이션, 미수신이 섞여 보이지 않도록 화면에 이렇게 나눠 둡니다.

| 구분 | 화면 표시 | 위치 |
| --- | --- | --- |
| 실행 환경 | "에뮬레이터 · 차량 데이터", "실차 · 차량 데이터", "시뮬레이션"(Pleos 차량 서비스가 없는 기기). 앱을 켠 직후 연결 중에는 "차량 연결 중" | 모든 화면 상단 |
| 실제 차량 값 | "주행거리 30,000km · 배터리 80%" | 작성 화면 미리보기, 인계 카드 아래 회색 줄(작성자·시각과 함께) |
| 미수신 | "주행거리 미수신"처럼 값마다. 다 못 받으면 "차량 값 미수신". 0으로 채우지 않음 | 같은 곳 |
| 이전 값 | 값 뒤 "(이전 값)" | 같은 곳 |
| 직접 입력 | 값 뒤 "(직접 입력)". 지금은 차량 값을 직접 입력하는 화면이 없어 나오지 않음 | 같은 곳 |
| 시뮬레이션 | 줄 끝 "· 시뮬레이션". Pleos 차량 서비스가 없는 기기에서만 | 같은 곳 |
| 목적지 출처 | "내비 목적지" / "직접 선택" | 인수 화면 목적지 칸 |
| 도착 근거 | "도착 · 내비 신호" / "도착 · 직접 확인" | 인수 화면 목적지 칸 |
| 음성으로 받은 글 | 저장 전 "음성으로 받은 내용이에요…" 확인 안내 | 작성 화면 |

시연 영상에서 Virtual Console로 바꾼 값, 직접 확인한 도착, 촬영 전 미리 넣은 인계는 자막으로 따로 밝힙니다(`docs/demo-script.md` 표기 원칙).

## 대표 시연 흐름

A(김하늘)가 반납하며 남기고 → B(이도윤)가 내비 목적지 한빛상사의 일을 먼저 받아 처리하고 → 시동을 껐다 켜도 C(박서연)에게는 끝나지 않은 일과 바뀐 내용만 갑니다. 장면별 화면과 문구는 `docs/demo-script.md`, 화면 문구 검사는 `DemoScriptTest`에 있습니다.

## 제외하거나 미루는 것

관리자 웹·서버 동기화·다차량(2차 PT 이후), Gleo(승인·실제 호출 확인 시), 경고등 자동 기록(권한 없음), 주행 중 음성 안내, 개인 모드·소모품 알림·예약·운행일지, 범용 AI 대화·자체 LLM·사진 자동 진단, 자동 운전자 식별·시동 시 자동 실행.
